# Asset primitive decomposition evidence

Date: 2026-08-08

## Purpose and boundary

This map is a **generation contract**, not just an observation. It decomposes
the remaining audited missing texture targets into a small set of common
primitives, shapes, materials, and palettes, and specifies each raster recipe
precisely enough that another generation process can reproduce the assets
byte-identically for intake into the standalone content pipeline.

The **remaining selection** is the set of missing targets that survive every
standalone stage on the `terrain-local-dojo` trajectory. The final stage
(`50-final-gui-revision.json`, cumulative fingerprint
`d98462e987b26ccd9c421df4b0e3e1a4dfbfe7502f83983284d7555282561178`) reports
454 missing entries: **0 blockstates, 0 models, 454 textures**. Every texture
is a `minecraft:` block or item texture, static (no `.png.mcmeta`), and
rasterized at 16x16. The raw inventory lives under
`.run/content-audits/terrain-local-dojo-stages/`; it is generated runtime state
and is not committed as source.

Higher-priority authored packs (Faithful 32x, Vanilla Evolved, Open Assets Lib,
GUI Revision, VoxeLibre) still replace every generated image in the composed
view. The generated provider is the deterministic bottom layer that converges
the audit inventory toward zero missing targets.

## Intake pipeline

```text
content audit  ->  content queue  ->  generated provider  ->  compose  ->  re-audit
     |                  |                   |                    |
 missing targets   generate/select/    GeneratedTextureLibrary  one hash-addressed
 (per trajectory,   resolved triage     + GeneratedContentPack   pack in the store;
  cumulative)       (ContentSubmission  emit assets under         authored wins and the
                    Queue)              assets/<ns>/textures/...  target drains as resolved
```

- **Input** — cumulative audit stage JSONs under a named stage directory. The
  standalone manifest's `generated-compatibility` source defaults to
  `.run/content-audits/terrain-local-dojo-stages`.
- **Triage** — `ContentSubmissionQueue.classify` marks a texture `generate`
  when `GeneratedTextureLibrary.distinct(family)` is true, otherwise `select`
  (generic placeholder; the real asset should be chosen from another package).
  Targets whose composed bytes differ from the generated bytes are `resolved`.
- **Generation** — `GeneratedTextureLibrary.generate(target)` produces the
  `BufferedImage` for a `generate` target; `GeneratedContentPack` emits model
  scaffolds. Higher-priority authored pack bytes win during compose.
- **Convergence** — repeated composition over a stable cumulative stage set is
  byte-identical, and the inventory converges toward zero because newly
  composed authored wins drain as `resolved`.

## Determinism contract

A conforming generator must treat each texture as a pure function of its
resource path:

- No mutable global state; output depends only on the target path and the fixed
  tables below.
- **PRNG** — `random(seed)`: FNV-1a 64-bit over the seed string (initial
  offset basis `0xcbf29ce484222325`, prime `0x100000001b3`, `xor ^= char`,
  `*= prime`), then a 48-bit LCG constructed as `new Random(hash)` and advanced
  in the standard Java order. Byte parity therefore requires reproducing the
  Java `Random` LCG exactly.
- Seed strings are the path basename without `.png`, plus the stable compound
  seeds `"grain-" + r/g/b` (hanging sign) and `"wood" + r/g/b` (wood bark).
- Color math is defined by `mix(a, b, t)`, `shade(c, delta)`, `clamp`, and
  `hsv(hue, s, v)` below; all integer RGB components are clamped to `0..255`.
- The current reference implementation is `GeneratedTextureLibrary`; focused
  tests and cross-process probes pin the generated-provider fingerprint order
  (a preserved sorted `TreeMap`) and the composer exclusion of macOS/editor
  metadata (`.DS_Store`, `._*`, `*~`, `Thumbs.db`).

## Vocabulary

### Primitives (12 raster operations)

| Primitive | Semantics |
| --- | --- |
| `fill` | Solid tile of one color. |
| `noise` | Per-pixel seeded `shade(base, +-delta)` over the whole tile. |
| `speckle` | Seeded per-pixel probability sprinkle (grain/highlight). |
| `rect` | Filled or outlined sub-rectangle. |
| `band` | Full-width horizontal strip. |
| `stripes` | Per-column vertical streak fill (bark). |
| `edge` | One-pixel dark/light border line. |
| `circle` / `ellipse` | Solid disk, or axis-aligned ellipse mask (egg). |
| `radial` | Polar stencil; coverage from distance and `sin(k*angle)`. |
| `diag` | Diagonal pixel runs (leaf pairs). |
| `crack` | Wandering vertical polyline (`x +-1` each row). |
| `alpha` | Translucent interior fill on an opaque frame. |

### Shapes (12 spatial templates)

`full tile` · `framed panel` · `vertical plank` · `egg` · `radial fan` ·
`pot+stem+leaves` · `face` · `cake+candle` · `bed` · `box` · `centered item
square` · `dial`

### Materials (8 texture generators)

`metal/copper plate` (noise + highlights) · `skin` (noise + facial features) ·

## Family classifier

The classifier is a pure function of the target path and is the **single**
classification point shared by generation and triage
(`GeneratedTextureLibrary.family`, consumed by `ContentSubmissionQueue`). Rule
order matters; rules are evaluated top to bottom:

1. `*_spawn_egg` -> `spawn_egg`
2. `*_wall_banner` or `*_banner` -> `banner`
3. `waxed_*` -> `waxed_copper`
4. `*_candle_cake` or `candle_cake` -> `candle_cake`
5. `*_stained_glass_pane` or `glass_pane` -> `glass_pane`
6. `*_wall_hanging_sign` or `*_hanging_sign` -> `hanging_sign`
7. `*_bed` -> `bed`
8. `*_shulker_box` or `shulker_box` -> `shulker_box`
9. `*_door` -> `door`
10. `*_wood`, `*_hyphae`, or `*_log` -> `wood`

## Per-family generation recipes

Coordinate system: `SIZE = 16`, origin top-left, one pixel per model texel.
`name` is the path basename without `.png`. `random(seed)` and `fill`,
`mix`, `shade`, `clamp`, `hsv` follow the determinism contract. Colors are
literal `rgb(r, g, b)`.

### spawn_egg (egg + speckle)

1. `base = hsv(floor(random.nextDouble() * 360), 0.35, 0.92)`.
2. Coverage mask `eggShape(x, y)`: `nx=(x-7.5)/5.12`, `ny=(y-7.5)/6.08`,
   draw `base` where `nx^2 + ny^2 <= 1`.
3. 14 specks: `cx=3+random.nextInt(10)`, `cy=3+random.nextInt(10)`,
   `radius=1+random.nextInt(2)`, color `mix(base, dye(random.nextInt(16)),
   0.55+random.nextDouble()*0.3)`, drawn as solid disks.

### banner (cloth)

1. `base = dyeColor(color)`; `color = name` minus `_banner`/`_wall_banner`
   suffix. `fill(base)`.
2. `emblem = mix(base, WHITE, 0.7)`; rows y=1..2 in every column except x=6..9.
3. Vertical bar x=7..8, y=5..10.

### waxed_copper (metal/copper plate)

1. `base` = copper stage from `COPPER` by name contains `exposed`/`weathered`/
   `oxidized`, else `copper`.
2. `noise` per pixel `+-(0..15)` (`shade(base, random.nextInt(16)-8)`).
3. `speckle` 6% per pixel `shade(base, 26)`.

### hanging_sign (vertical plank)

1. `fill(woodColor(name))` where `woodColor` strips `stripped_` then matches a
   wood name prefix, else oak.
2. Row 0 `mix(wood, black, 0.5)`; row 15 `mix(wood, black, 0.4)`.
3. Bracket notches x=4..5 and x=10..11, y=1..2, `mix(wood, black, 0.7)`.
4. Grain `speckle`: seed `"grain-r-g-b"`, 6% per pixel `mix(wood, black, 0.3)`.

### wood (wood/bark)

1. `bark = woodColor(name)`. Per column x: `streak = 1+random.nextInt(2)`,
   `tone = mix(bark, black, random.nextDouble()*0.35)`; fill the column with
   `tone`; 8% per pixel `mix(tone, WHITE, 0.2)`, 8% per pixel
   `mix(tone, black, 0.25)`.
2. Dark band row y=4..4, `mix(bark, black, 0.45)`. Seed `"wood-r-g-b"`.

### candle_cake (cake+candle)

1. `fill(232, 217, 173)`; rows y=0..4 `fill(240, 225, 214)`.
2. Candle `candle = dyeColor(color)` (plain `candle_cake` is white): x=7..8,
   y=5..9, plus base x=6..9 at y=4.
3. Flame dots `(8,3) = (255,220,110)`, `(7,2) = (255,200,60)`.

### glass_pane (framed panel + alpha)

1. `tint = dyeColor(color)` (plain `glass_pane` is white).
2. Frame where `x<=1 || x>=14 || y<=1 || y>=14`, alpha 235, `tint`.
3. Interior alpha 120 `tint`; inner area x=2..13, y=2..13 alpha 90
   `mix(tint, WHITE, 0.35)`.

### shulker_box (box)

1. `fill(dyeColor(color))` (plain `shulker_box` is purple).
2. Top band y=0..3 `mix(dye, WHITE, 0.3)`; dark line y=4 `mix(dye, black,
   0.35)`; bottom line y=15 `mix(dye, black, 0.45)`.

### door (framed panel)

1. `base = doorColor(name)` — iron: `(176,176,176)`; copper variants: the
   `COPPER` stage; `stripped_` prefix stripped then wood prefix match; else oak.
2. `fill(base)`; frame where `x<=1 || x>=14 || y<=1 || y>=14`,
   `mix(base, black, 0.4)`.
3. Recessed panels `mix(base, black, 0.22)`: x=3..6 y=3..6; x=9..12 y=3..6;
   x=3..12 y=9..12.
4. Handle `mix(base, WHITE, 0.35)` at `(13,8)` and `(13,9)`.
5. Seam `speckle`: x=8, y=3..12, 12% per pixel `mix(base, black, 0.3)`.

### potted_plant (pot+stem+leaves)

1. Pot x=3..12, y=9..13 `(150,93,61)`; rim x=5..10, y=14 `(150,93,61)`.
2. Stem x=8, y=3..8 `(70,120,50)`.
3. Leaf pairs y=4..7 `(88,145,62)` at x=`8-(y-3)` and x=`8+(y-3)`.

### bed (bed)

1. `fill(mix(dye, WHITE, 0.25))`.
2. Headboard x=0..5, y=2..14 `(244,240,234)`.
3. Dark border where `x<1 || x>=15 || y>=15`, `mix(dye, black, 0.4)`.

### generic_item (centered item square)

1. `base = itemTone(name, random)` (tone table below).
2. Interior x=3..12, y=3..12 `noise` `shade(base, random.nextInt(12)-6)`.
3. Highlight rows y=2..4, x=3..12 `shade(base, 30)`.

### head (face)

1. `skin` by species substring: creeper `(104,188,96)`, wither `(66,66,66)`,
   skeleton `(200,200,200)`, piglin `(233,172,150)`, zombie `(108,148,98)`,
   dragon `(62,62,62)`, else `(224,181,149)`.
2. `fill(skin)`; `noise` `shade(skin, random.nextInt(10)-5)`.
3. Eyes x=4..5 and x=10..11, y=6..7 `(60,60,70)`; mouth x=7..8, y=11..12
   `(80,80,90)`.

### coral_fan (radial fan)

1. For each pixel: `dx=x-8`, `dy=y-8`, `r=sqrt(dx^2+dy^2)`,
   `angle=atan2(dy,dx)`, `ribs=|sin(angle*5)|`.
2. Draw `coralColor(name)` (match before `_wall_fan` in `CORAL`, else gray
   `(180,180,180)`) where `r < 7 && (ribs > 0.75 || r < 2)`; all other pixels
   transparent.

### infested (stone noise + cracks)

1. `fill(125,125,125)`; `noise` `shade(base, random.nextInt(16)-8)`.
2. Two `crack` polylines: start x random at y=0, walk y 0..15 with x +=
   `random.nextInt(3)-1` (clamped), drawing `(70,70,70)`.

### generic_block (stone noise)

1. `base = blockTone(name, random)` (tone table below).
2. `noise` `shade(base, random.nextInt(14)-7)`; `speckle` 4% per pixel
   `shade(base, -26)`.

## Color math

- `mix(a, b, t)` = per-channel `a + (b - a) * t` rounded to int.
- `shade(c, delta)` = per-channel `clamp(c + delta)`.
- `hsv(hue, s, v)`: standard hue-wheel chroma/`x`/`m` computation; used only
  for the spawn-egg pastel base.
- `clamp` bounds each channel to `0..255`; ARGB alpha is explicit per recipe.

## Intake handoff for a new generation process

To stand up a conforming generator:

1. Reuse the classifier and `distinct` rule unchanged so triage and generation
   cannot drift.
2. Reproduce the FNV-1a 64-bit seed + Java `Random` LCG order, the fixed
   palette/tone tables, and the color math to keep PNG bytes identical.
3. Emit each `generate` texture at `assets/<namespace>/textures/<path>.png`
   under the `generated-compatibility` provider tree, 16x16, RGBA; static
   textures need no sidecar.
4. Keep `generic_block`/`generic_item` in the `select` lane so authored packs
   are preferred; re-audit after compose and let authored wins drain as
   `resolved`.
5. A refactor of the existing library may express every family as
   `render(shape, material, palette)` over the shared primitive set; the family
   classifier and the recipes above are the invariants to preserve.
